# 東京旅遊日語 30 天衝刺 🏮

依 [`japanese-sprint-app-spec.md`](japanese-sprint-app-spec.md) 實作的純前端日語複習 Web App。
出發日 **2026-08-27**，全 App 顯示倒數天數。零相依、無框架、無 SDK。

**線上版**：https://louise-pei.github.io/japaneseisgood/

## 怎麼開始用

用 Safari 開上面的網址 → 分享 → **加入主畫面**。之後點開就跟一般 App 一樣，而且**沒有網路也能用**（service worker 會把整個 App 快取起來，這點在東京地下街很重要）。

想要完全不碰網路的版本，把 `東京日語衝刺.html` 這一個檔案 AirDrop 到手機也行 —— 功能完全相同。

> ⚠️ 進度預設只存在該裝置。要跨裝置接續，到「⚙️ 設定與備份 → 跨裝置同步」產生一組同步碼（需先完成下方的雲端設定）。

## 每日 30 分鐘

App 會依當天的主題自動組出關卡，**沒有內容的關卡不會出現**：

| 關卡 | 時間 | 內容 |
|---|---|---|
| 📋 今日盤點 | 2 分 | 只在還有沒盤點過的卡時出現。看中文試著開口 → 點卡片 → **答案一定翻出來** → 三選一：秒答／想一下才想到／說不出來 |
| ☀️ 暖身 | 3 分 | 昨天複習過的卡，四選一（低負荷起步） |
| 🎴 主複習 | 8 分 | 到期卡：看中文 → **大聲說出日語** → 翻卡 → 自評 0–5 |
| 🗣️ 情境對話 | 13 分 | 當日主題角色扮演，可播範例發音、錄自己回放對照 |
| 🈶 漢字快閃 | 3 分 | 招牌漢字大字（64px）四選一，答錯自動排入 SRS |
| ✍️ 反思 | 1 分 | 一句提示、寫一行，然後慶祝畫面 |

### 盤點為什麼長這樣

第一版是「三天前置診斷」：一次掃 116 張，按下「生疏了」卡片就翻頁。問題是**它從來不告訴你答案** —— 那三天完全沒學到東西，而且冷啟動的產出型回憶是負荷最高的任務型態，放在第一天最容易讓人放棄。

現在改成：盤點拆進每日課程、只盤當天主題的卡（情境相近，回憶容易得多），而且**不管想不想得起來，答案都會翻出來**。所以盤點同時就是一次曝光，不是純考試。Day 1 就開始真正的學習。

三個選項餵給 SRS 的東西也不同：

- **秒答** → 不進每日複習，末期交錯模擬時才隨機抽查
- **想一下才想到** → 進 SRS，但釋出時 `repetitions = 1`，第一次答對就直接排到 3 天後
- **說不出來** → 進 SRS，從 0 開始

## 發音

每張卡、每句對話旁邊都有 **🔊 正常速**與 **🐢 慢速**（預設 0.75×，設定頁可改 0.5×）。搭配參考答案下方原有的錄音鍵，形成完整的「聽範例 → 跟著唸 → 錄自己 → 回放對照」。慢速用 `playbackRate` 且維持音高，不會變成怪腔調。

刻意**不做自動播放** —— 在電車上或餐廳裡突然出聲很尷尬，要聽就自己按。

店員／站務員的台詞用**另一個聲音**，跟參考答案區隔開，比較接近實際要面對的「聽陌生人講話」。

### 為什麼是預先產生的音檔

`speechSynthesis`（瀏覽器即時合成）看起來更省事，但使用者主要從**主畫面圖示**開啟，而 iOS 在 standalone 模式下的語音／音訊 API 長期不穩定，各裝置的日語語音品質也不一致，Android 甚至可能沒安裝日語語音。

改用 macOS 內建的 `say` 事先產生 148 則 AAC 音檔（**約 2 MB**），品質固定、離線可靠、每台裝置一致。

### 離線語音包

設定頁的「下載語音包」會把全部音檔存進瀏覽器快取（獨立的 `jp-audio-v1`，改版時不會被清掉）。平常也是聽到哪快取到哪。**出發前在家裡 Wi-Fi 按一次就好。**

> ⚠️ iPhone 側邊的**靜音開關**會讓網頁音訊完全無聲 —— 這是最容易誤判成「功能壞掉」的坑。設定頁有「試聽」按鈕可以在自己的裝置上確認。

### 重新產生音檔

改了 `data.js` 的內容之後：

```bash
python3 make_audio.py
```

只會補產新增或改動的部分（已存在就跳過），並清掉不再需要的舊檔。腳本會從 `say -v '?'` **動態解析**日語語音全名 —— 不能寫死，因為短名稱（如 `Reed`）會抓到英語版並產出無聲檔案，而完整名稱會隨系統語言變動。

合成內容的取捨：句子用原文（有上下文，TTS 斷詞比較準），單字與招牌漢字改用假名欄位（實測 `一人`、`両替` 這類唸原文會誤讀）。

## 跨裝置同步（選用）

不做帳號密碼，改用**同步碼**：一組 12 碼的隨機字串，在另一台裝置輸入就能合併進度。不收 Email、不存任何個資。家人各自產生自己的碼，彼此完全隔離。

### 設定（一次性，約 5 分鐘）

1. 到 https://supabase.com 開一個免費專案（不需要信用卡）
2. 進 **SQL Editor**，貼上 [`supabase-setup.sql`](supabase-setup.sql) 整段並執行
3. 到 **Settings → API**，把 **Project URL** 和 **anon / public key** 填進 [`config.js`](config.js)
4. `python3 build.py` 重新打包，push 上去

設定完成後，「⚙️ 設定與備份」裡就會出現同步碼。

> ⚠️ `config.js` 只能放 **anon / public key** —— 它設計上就是要公開的。**千萬不要**貼 `service_role` key。

### 安全性

資料表開了 RLS 但**刻意不建立任何 policy**，所以拿 anon key 的人無法直接讀寫那張表。對外只暴露 `pull` / `push` 兩支 `security definer` 函式，都必須帶對同步碼。同步碼用 12 碼、去掉易混淆字元（無 `0 O 1 I l`）的字母表，約 10¹⁸ 種組合。

### 合併規則

兩台各練各的也不會弄丟任何一邊：

- **卡片**：逐張取「最近複習過」的那份；盤點結果只要有一邊做過就算數
- **每日紀錄**：以日期聯集，同一天以本機為準
- **streak**：採用 `lastDay` 較晚的那份，最佳紀錄取大、補簽卡取小（保守）
- **反思 / 一日東京紀錄**：去重聯集
- **盤點統計**：從卡片重算，避免兩邊相加變成重複計數

同步時機：開啟 App 時拉、完成當日課程後推、切到背景時補推，另外有手動「立即同步」。**全部失敗靜音** —— 沒網路時只會跳提示，學習流程一秒都不會被擋。

### 開發

```bash
python3 -m http.server 8777
```

改完內容後重新打包：

```bash
python3 build.py
```

單檔版預設**不含音檔**（117 KB）。要一個連發音都自帶、完全不需要網路的單一檔案：

```bash
python3 build.py --with-audio
```

音檔會以 base64 內嵌，產出約 2.4 MB 的自足檔案，AirDrop 到手機直接開就有聲音。

> service worker 採 cache-first ＋ 背景更新，所以改版後使用者**第二次**開啟才會看到新版。要強制立即更新，改 `sw.js` 裡的 `CACHE` 常數（例如 `jp-sprint-v3`）。

## 實作重點

**SRS 排程**：規格書指定的簡化 SM-2。`quality < 3` 一律隔天再見；答對時間隔為 1 → 3 → `interval × EF`；EF 下限 1.3。加上**衝刺上限** —— 間隔不超過「距出發剩餘天數的一半」，確保每張卡出發前都還會再見 1–2 次。

**卡片釋出節奏**：盤點標為要複習的卡不會一次全丟出來，而是依課表階段、每天 8 張慢慢釋出（今日到期 > 25 張時自動降為 4 張並提示）。今天要盤點的卡不會同時當新卡出現。

**Streak 與補簽卡**：跨日判定用本地時區。漏一天可用補簽卡救回（每月 2 張、月初自動歸還）；漏兩天以上才算斷。

**內容**：116 張卡（45 張高頻 ★）涵蓋 basics / repair / restaurant / shopping / transport / hotel / kanji 七類，5 組情境對話（含食券機分支）。全部釋義互不重複，所以四選一不會出現兩個正解。
