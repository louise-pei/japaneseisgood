# 東京旅遊日語 30 天衝刺 🏮

依 [`japanese-sprint-app-spec.md`](japanese-sprint-app-spec.md) 實作的純前端、單機可用日語複習 Web App。
出發日 **2026-08-27**，全 App 顯示倒數天數。

## 怎麼開始用

**線上（最方便）**：https://louise-pei.github.io/japaneseisgood/
用 Safari 開啟 → 分享 → **加入主畫面**，之後就像一般 App 一樣點開。

**離線單檔**：把 `東京日語衝刺.html` 這一個檔案 AirDrop 到 iPhone，用 Safari 開啟後同樣可以加入主畫面，完全不需要網路。

**電腦上**：直接用瀏覽器打開 `東京日語衝刺.html`（或 `index.html`）。

> ⚠️ 進度只存在該裝置的瀏覽器 localStorage。換手機或清除 Safari 資料前，記得先進「⚙️ 設定與備份 → 匯出 JSON 備份」。

## 使用流程

### 1. 診斷分流（第一次開啟）
快速掃過全部 116 張卡，只看中文、自問說不說得出日語，二選一：

- **已經會了** → 標記 `known`，不進每日複習，但 Day 22 之後的交錯模擬會隨機抽查
- **生疏了** → 進入 SRS 候補池

每次最多 50 張、預設分 3 天做完（也可以按「不等了，繼續診斷」一次做完）。診斷做完才解鎖每日課程。

### 2. 每日 30 分鐘（固定 5 段）

| 段 | 時間 | 內容 |
|---|---|---|
| ☀️ 暖身 | 3 分 | 昨天複習過的卡，四選一（低負荷起步） |
| 🎴 主複習 | 8 分 | 到期卡：看中文 → **大聲說出日語** → 翻卡 → 自評 0–5 |
| 🗣️ 情境對話 | 15 分 | 當日主題角色扮演，支援錄音回放自我對照 |
| 🈶 漢字快閃 | 4 分 | 招牌漢字大字（64px）四選一，答錯自動加入 SRS |
| ✍️ 反思 | 30 秒 | 一句提示、寫一行，然後慶祝畫面 |

### 3. 30 天課表

| 階段 | Day | 內容 |
|---|---|---|
| 診斷重啟 | 1–3 | 全卡診斷分流 |
| 區塊 A | 4–9 | 問候／數字／時間 ＋ 餐廳 |
| 區塊 B | 10–15 | 購物 ＋ 交通問路 |
| 區塊 C | 16–21 | 飯店 ＋ 招牌漢字閱讀 |
| 交錯模擬 | 22–27 | 「一日東京」串場，混合所有情境 |
| 高頻精煉 | 28–30 | 只練 45 張高頻卡 ＋ 修復策略句 |

晚開始也沒關係：階段是用「已過天數 ÷ 到出發的總跨度」等比對映的，會自動壓縮。

### 4. 「一日東京」（Day 22 或剩 ≤6 天解鎖）
19 個關卡的連續劇情：成田買 Suica → 問月台 → 飯店寄行李 → 食券機拉麵 → 藥妝店退稅 → 迷路問路 → 回飯店 check-in。

## 實作重點

**SRS 排程**：規格書指定的簡化 SM-2。`quality < 3` 一律隔天再見；答對時間隔為 1 → 3 → `interval × EF`；EF 下限 1.3。加上**衝刺上限** —— 間隔不超過「距出發剩餘天數的一半」，確保每張卡出發前都還會再見 1–2 次。以 7/29 起算，上限是 14 天。

**卡片釋出節奏**：診斷標為「生疏」的卡不會一次全丟出來，而是依課表階段、每天 8 張慢慢釋出（今日到期 > 25 張時自動降為 4 張並提示）。這是為了讓區塊 A/B/C 的分段真的有意義 —— 否則診斷完隔天就會湧入 80 幾張。

**Streak 與補簽卡**：跨日判定用本地時區。漏一天可用補簽卡救回（每月 2 張、月初自動歸還）；漏兩天以上才算斷。

**內容**：116 張卡（45 張高頻 ★）涵蓋 basics / repair / restaurant / shopping / transport / hotel / kanji 七類，5 組情境對話（含食券機分支），全部釋義互不重複，所以四選一不會出現兩個正解。
